You are given observations of human choices in the CPC18 Track II task (Individual behavior).

Each problem presents two gambles: Option A and Option B.
Each gamble is defined by:
- a high outcome and its probability,
- a low outcome,
- a lottery shape and number of outcomes.

You will see a history of previous trials for the SAME participant and SAME problem.
Each problem consists of 25 trials, organized into 5 blocks of 5 trials.
Feedback is only available after the first block.

IMPORTANT — Evaluation metric:
CPC18 is evaluated using log-likelihood.

Your program must return a probability:

    P(action = 1)

where:
- action 0 = choose Option A
- action 1 = choose Option B

The observed human action is scored by log-likelihood:
- if the human chose B (action 1), the score uses log(p)
- if the human chose A (action 0), the score uses log(1 - p)

where p is your returned probability of choosing action 1.

The goal is to MAXIMIZE log-likelihood.
Higher log-likelihood is better (values closer to 0 are better).

Examples:
- log-likelihood = -0.2 is better than -1.5
- returning p = 0.8 means high likelihood of choosing Option B
- returning p = 0.2 means high likelihood of choosing Option A

Key implications:
- Your output should be a smooth probability in [0, 1], not only hard labels 0 or 1.
- Avoid returning exactly 0.0 or exactly 1.0, as this leads to very poor log-likelihood when incorrect.
- Good solutions estimate human choice probabilities, not just deterministic decisions.
- Pure always-A or always-B strategies perform poorly.
- Simply copying past actions may overfit and generalize poorly.

Your goal:
Write Python code that reproduces human behavior by maximizing log-likelihood.
This requires estimating the probability that the participant chooses Option B (action 1).

HARD CONSTRAINTS:
- The program MUST use problem fields:
  Ha, pHa, La, Hb, pHb, Lb, LotShapeA, LotNumA, LotShapeB, LotNumB, Amb, Corr.
- Do NOT rely only on copying or smoothing history.action.
- Do NOT implement pure inertia or majority-vote policies that ignore the problem.

You must generate a program implementing:

def choose(problem, history):
    """
    problem: dict with keys
        - Ha: float
        - pHa: float
        - La: float
        - LotShapeA: str
        - LotNumA: int

        - Hb: float
        - pHb: float
        - Lb: float
        - LotShapeB: str
        - LotNumB: int

        - Amb: int
        - Corr: int

    history: list of dicts with keys
        - action: int (0 = A, 1 = B)
        - feedback: float or None

    return: float, probability of choosing action 1 (Option B)
            Must be in [0, 1]
    """

Guidelines:
- Use both problem and history to estimate P(action=1).
- Prefer smooth probabilistic decision rules (e.g., sigmoid/logistic).
- Avoid sharp deterministic switching unless strongly justified.
- Clip probabilities to avoid exact 0 or 1 (e.g., [1e-9, 1 - 1e-9]).

Constraints:
- Pure Python.
- Deterministic code only (no randomness or sampling).
- Use only the provided problem and history.
- Do not call external APIs.

Provide only the code for choose(...) as a complete function body.
